# 《码上飞升》V0.3 产品设计方案

> 阶段：V0.3「世界展开阶段」· 产品设计（本阶段只设计，不进行大规模开发）。
> 依据：`docs/V0.3_REVIEW.md`（实机体验审查）。
> 核心命题：把《码上飞升》从「学习界面修仙风」升级为「可生活的代码修仙世界」——
> 玩家不再觉得「我在做 Python 练习」，而是「我生活在一个代码即法则的世界，修炼就是写代码」。

---

## 1. 产品目标

### 1.1 核心目标

补足当前版本缺失的「生活在修仙世界中的感觉」，四大支柱：

| 支柱 | 现状 | V0.3 目标 |
| --- | --- | --- |
| 空间 | 地图是功能卡片菜单 | 可探索的二维「区域-地点」地图（3 区域、12+ 地点、连接与解锁） |
| 人物 | NPC 是底部图标按钮 | NPC 绑定地点、在场状态、好感度与专属成长线 |
| 事件 | 主线线性推进、世界静止 | 主线章节 + 支线 + 随机奇遇 + 境界剧情，世界随进度变化 |
| 选择 | 玩家被当前任务牵引 | 多线自由目标（主线/支线/功法修炼/探索），全部入口在地图上可见 |

### 1.2 铁律（继承并强化）

- 代码始终是这个世界的力量体系；**所有成长必须以真实代码验证为门槛，禁止纯数值挂机**。
- 教学必须准确：世界观包装只负责「动机与氛围」，知识讲解保持直白。
- 不更换技术栈、不推翻现有架构、不开发 3D、不开发联机。
- 数据驱动优先，最大化复用现有 NPC/对话/任务/秘境/存档体系。

### 1.3 验收导向（V0.3 完成判定）

1. 玩家可从地图「走到」青云宗 / 青云城 / 后山秘境 3 个区域、12+ 个地点，地点间有连接与解锁条件。
2. 至少 4 位核心 NPC（青玄子/云游子/玄机长老/掌门）绑定地点并具备专属成长线；好感度系统生效。
3. 主线章节 ≥3 章；随机奇遇 ≥8 种；境界剧情覆盖每次突破；支线任务（任务堂）≥5 个。
4. 功法系统：首批 12 门功法独立数据化，4 级熟练度成长，演武场修炼/考核闭环。
5. 长期成长：功法图鉴/奇遇图鉴/宗门贡献/好感度关系全部落地，均有即时反馈。
6. 全部新玩法通过沙箱真实执行验证；旧功能零回归（pytest / E2E 全绿）。

## 2. 世界地图设计

### 2.1 世界观定位

故事发生在「青云山」一隅：青云宗是此界少有的「以代码入道」的宗门；山外是凡人聚居的青云城；山后是灵气紊乱的秘境禁地。天地规则（Python 解释器）客观存在，掌握规则者即是修士。

### 2.2 区域与地点

| 区域 | 解锁条件 | 地点 | 作用 |
| --- | --- | --- | --- |
| **青云宗** | 初始开放 | 山门 | 进入/离开宗门的必经之路；守门石狮对话（世界观） |
| | | 洞府 | 主线修行、角色信息、存档（现状升级为地点） |
| | | 藏经阁 | 功法总览、功法树、玄机长老 |
| | | 任务堂 | 主线/支线领取、宗门贡献查看（新地点） |
| | | 演武场 | 功法修炼挑战与考核（新地点） |
| | | 炼丹房 | Debug 心魔（现状迁移） |
| | | 渡劫台 | 天劫试炼（现状迁移） |
| **青云城** | 炼气三层 / 主线推进 | 城门 | 往返宗门与城区 |
| | | 商铺 | 用灵石/宗门贡献兑换道具 |
| | | 客栈 | 消息传闻、奇遇线索（随机） |
| | | 街市 | 支线 NPC（小月、神秘散修、落魄书生） |
| **后山秘境** | 炼气五层 / 主线推进 | 山道 | 通往秘境入口的通道，可触发奇遇 |
| | | 秘境入口 | 云游子、三处秘境总览（现状迁移） |
| | | 奇遇点 | 随机遭遇（灵兽/遗迹/残卷） |

### 2.3 地图关系（连通图）

```
                 ┌──────────────┐
                 │  青云宗       │
                 │ 山门 ⇄ 洞府    │
                 │  ↕     ↕     │
                 │ 藏经阁 炼丹房  │
                 │  ↕     ↕     │
                 │ 任务堂 渡劫台  │
                 │  ↕            │
                 │ 演武场         │
                 └──────┬───────┘
            山门 ⇄ 城门口        │ 山道（后山）
                        │        ↓
                 ┌──────┴────┐  ┌──────────────────┐
                 │ 青云城      │  │ 后山秘境          │
                 │ 商铺·客栈   │  │ 秘境入口 ⇄ 奇遇点  │
                 │ 街市(NPC)   │  │  ↕               │
                 └───────────┘  │ 青云/万象/天宫      │
                                └──────────────────┘
```

- 实线为常规往返（任何已解锁地点间可一键移动）；箭头为单向剧情路径（如后山在特定章节后才开放）。
- 地点间关系数据化：`connections` 记录可达关系，`unlock` 记录解锁条件。

### 2.4 解锁条件

| 对象 | 条件 | 说明 |
| --- | --- | --- |
| 青云城 | 境界 ≥ 炼气三层 或 完成「青云城之约」主线 | 数据驱动 |
| 后山秘境 | 境界 ≥ 炼气五层 且 主线推进至「后山异动」 | 数据驱动 |
| 商铺 | 进入青云城即可 | |
| 演武场 | 习得任意功法 | |
| 任务堂 | 入门（凡人期结束后） | |

### 2.5 技术形态

- **「区域-地点」二维节点图**（非自由行走）：每区域一张地点面板，地点为带坐标（x,y）的可交互卡片，卡片间以连线示意可达关系；顶部区域切换器（青云宗/青云城/后山）。
- 现有 8 张功能卡片（洞府/炼丹房/渡劫台/藏经阁/机缘簿/秘境/储物袋/成就碑）映射为对应地点；新增任务堂、演武场、商铺、客栈、街市、山门、城门、山道、奇遇点等地点。
- 数据：`game/data/world.json`（见第 7 章）。

## 3. NPC 系统设计

每位 NPC 均设计：背景 / 性格 / 对话风格 / 任务关系 / 成长路线 / 所在地点 / 好感度。

### 3.1 青玄子（授业师尊）—— 新手引导 · AI 导师 · 主线剧情

- **背景**：青云宗传功长老，《Python 真解》守护者，以「引而不发，点而不破」之道渡人入道。
- **性格**：温和寡言，惜才护短，极重「自证」。
- **对话风格**：打机锋、给方向不给答案；常以设问收尾。
- **任务关系**：新手引导（现状）；炼气期主线关键节点（授意调查灵脉异动）；突破节点传授心法。
- **成长路线**：
  1. 凡人~炼气：引导入道，教导基础真言。
  2. 筑基：授「筑基心法」，交代宗门灵脉真相。
  3. 金丹：托付宗门秘辛（真解来源）。
  4. 化神：揭示《Python 真解》与天地规则的最终关系。
- **好感度**：聆听教诲/请教修行 +2~5；完成师尊指派任务 +10；好感 ≥60 解锁「师尊的过往」专属对话。

### 3.2 云游子（秘境引路人）—— 秘境 · 奇遇 · 探索

- **背景**：四海云游的散修，手持罗盘知天下秘境，行踪不定。
- **性格**：洒脱神秘，嬉笑藏机锋。
- **对话风格**：谜语与「机缘论」，信息半藏半露。
- **任务关系**：解锁三秘境（现状）；提供奇遇线索（客栈消息联动）；后山探索引导。
- **成长路线**：
  1. 炼气：指引青云秘境。
  2. 金丹：开启万象幻境。
  3. 化神：开启代码天宫，揭示「秘境之源」。
  4. 高好感：赠送「云游手记」（奇遇图鉴加速）。
- **好感度**：赠酒（道具）/解谜对话 +3；完成其指路奇遇 +8。

### 3.3 玄机长老（藏经阁执事）—— 功法 · 技能树

- **背景**：藏经阁执事，功法渊博，执掌功法传承。
- **性格**：严厉古板，爱考校，见勤奋则喜。
- **对话风格**：以功法考校代替寒暄，「先答我一个问题」。
- **任务关系**：功法树解锁、功法修炼资格、技能点（功法等级）。
- **成长路线**：
  1. 炼气：传授基础功法（变量/循环/函数）。
  2. 筑基：开放中阶功法与功法树。
  3. 金丹：开放高阶功法。
  4. 高好感/圆满功法：发布「自创功法」项目式任务（综合运用多项知识点）。
- **好感度**：完成考校 +5；功法升级 +8。

### 3.4 掌门（青云真人）—— 宗门剧情 · 高级任务

- **背景**：青云宗掌门，筑基后期，执掌宗门大局；对灵脉异动早有察觉。
- **性格**：威严务实，护短，不轻易许诺。
- **对话风格**：宗门事务口吻、训诫、托付重任。
- **任务关系**：宗门主线剧情推进者、高级任务发布者、宗门危机事件核心。
- **成长路线**：
  1. 入门：拜见掌门（炼气一层后自动触发）。
  2. 炼气三层：授命前往青云城探查。
  3. 炼气五层：组织后山秘境探查队。
  4. 筑基：回山述职，授予「青云行走」身份。
  5. 金丹：共商宗门秘辛。
- **好感度**：宗门贡献兑换；完成宗门任务 +10。

### 3.5 好感度系统（通用）

- 数据：`npc_affinity: dict[str, int]`（0~100，新增玩家字段）。
- 来源：对话选项（+2~5）、完成该 NPC 相关任务（+10）、送礼（道具→好感，+15）。
- 效果（数据驱动）：解锁新对话节点、专属支线、功法折扣、剧情选项。
- 显示：NPC 界面好感度条 + 关系称谓（陌生/相识/相知/莫逆）。

### 3.6 NPC 在场

- 每个 NPC 绑定 `location`；对应地点卡片显示 NPC 头像（可点击对话）。
- 剧情阶段可改变在场状态（如掌门闭关、云游子外出历练），世界因此「会动」。

## 4. 功法系统设计

### 4.1 定位

功法 = Python 知识点技能。从「境界自动授予的教学回顾」升级为「可修炼、可成长、可收集」的系统，是 V0.3 长期成长的核心载体。

### 4.2 功法名录（首批 12 门，覆盖现有知识点）

| 功法 | 对应知识点 | 来源 |
| --- | --- | --- |
| 《真言诀》 | print / 输出 | 凡人期 |
| 《变量吐纳诀》 | 变量 | 炼气二层 |
| 《辨型术》 | 数据类型 / 转换 | 炼气三层 |
| 《分支定式》 | if / elif / else | 炼气中 |
| 《循环周天诀》 | for / while | 炼气中 |
| 《函数凝元术》 | 函数定义与调用 | 炼气高 |
| 《列表储物术》 | 列表 | 筑基 |
| 《字典观星术》 | 字典 | 筑基 |
| 《异常破障诀》 | try / except | 筑基 |
| 《模块引灵术》 | 模块导入 | 金丹 |
| 《文件炼器术》 | 文件读写 | 金丹 |
| 《物华天宝诀》 | 类与对象（OOP） | 金丹 |

### 4.3 功法等级与效果

| 等级 | 熟练度 | 解锁效果 |
| --- | --- | --- |
| 入门 | 习得即入门 | 解锁功法条目 |
| 小成 | 40 | 该知识点任务奖励 +10% |
| 大成 | 70 | 悟性 +1；解锁功法修炼挑战（高难） |
| 圆满 | 100 | 授予「XX·圆满」称号；该知识点试炼/秘境奖励 +10% |

> 数值保守，避免膨胀；加成绑定「该知识点」的真实任务，不会造成挂机收益。

### 4.4 解锁条件

- **习得**：突破对应境界自动获得（兼容现状），玄机长老处可查看。
- **升级**：熟练度达标后，在演武场通过「功法考核」（真实代码挑战）升级。
- **功法树**：玄机长老界面展示；前置功法大成解锁高阶功法（如《列表储物术》需《变量吐纳诀》小成）。

### 4.5 学习方式（全部真实代码，禁止挂机）

| 方式 | 熟练度 | 说明 |
| --- | --- | --- |
| 完成该知识点任务 | +20 | 主线/支线/Debug 中运用即涨 |
| 演武场·功法修炼 | +30/次 | 随机生成该知识点小挑战（复用秘境挑战生成器，沙箱自检可解） |
| 综合试炼 | +10 | 渡劫/秘境通关时按用到的知识点少量加成 |

> 熟练度满后必须通过演武场「考核」才升级——升级本身也是一次真实代码验证。

### 4.6 数据

- 新增 `game/data/techniques.json`：`id / name / knowledge / desc / levels[效果] / prereq（前置）/ realm（习得境界）`。
- 玩家新增字段：`technique_progress: dict[str, int]`（熟练度）、`technique_level: dict[str, int]`（等级 1~4）。
- 现有 `techniques.py` 从「境界派生」改为「techniques.json + 境界自动习得映射」双轨，保持向后兼容。

## 5. 剧情系统设计

### 5.1 主线（章节制）

主线按大境界分章，每章 3~5 个剧情节点（`story.json`），节点可触发任务/对话/奇遇/地图解锁/世界状态变化。

| 章节 | 剧情 | 节点示例 |
| --- | --- | --- |
| 凡人篇 | 入道（现状） | 残卷入道 → 唤醒灵牌 → 拜师 |
| **炼气篇（V0.3 核心）** | **宗门危机** | 灵脉异动 → 授命查探 → 青云城风云 → 后山寻源 → 对峙真相 → 筑基 |
| 筑基篇 | 下山历练 | 青云行走 → 商会委托 → 旧友重逢 |
| 金丹篇 | 宗门秘辛 | 真解来源 → 上古遗迹 |
| 元婴/化神篇 | 天机 | 预留节点 |

炼气篇剧情梗概：青云宗灵脉（灵气来源）近日异动，掌门命你查探；线索指向青云城的「墨阁」（以假代码牟利的邪修组织）；追踪至后山秘境，发现灵脉被「伪心法」（错误代码）污染；你以真代码修复灵脉节点，突破筑基，宗门危机暂解。

### 5.2 支线（宗门任务）

- 发布地点：任务堂。
- 全部为真实代码任务包装：采集灵草（文件读写）、巡山布阵（循环）、炼丹房补方（Debug）、整理玉简（字典/列表）、护送商队（条件分支）。
- 奖励：修为 + **宗门贡献**（新数值，可兑换道具/功法/好感）。

### 5.3 奇遇（随机事件）

- 触发：在「山道 / 客栈 / 奇遇点」等地点探索时按概率触发（每日/每次进入限次，防刷）。
- 事件池（首批 ≥8）：灵兽拦路（条件）、秘境遇险（异常）、奇人赠法（函数）、心魔夜袭（Debug）、天降机缘（随机挑战）、故人求助（列表）、残卷现世（字符串）、器灵考校（OOP）。
- 实现：复用秘境挑战生成器（模板 + 参数随机 + 沙箱自检），保证随机事件可解可验证。
- 奖励：修为 / 道具 / 好感 / **奇遇图鉴条目**。

### 5.4 境界剧情

- 每次突破：展示境界 intro（现状）+ 突破后触发「境界剧情节点」（新对话/事件/世界状态变化）。
- 例：突破炼气三层 → 掌门传讯解锁青云城；突破筑基 → 回山述职、获得「青云行走」称号。

## 6. 长期成长体系

### 6.1 六大留存动机

1. **境界攀升**：力量感（现有，扩展新境界剧情）。
2. **功法修炼**：成长感（V0.3 功法熟练度/等级/功法树）。
3. **世界探索**：空间感（新区域/新地点/奇遇点）。
4. **剧情推进**：事件感（主线章节/支线/奇遇）。
5. **NPC 关系**：人物感（好感度/专属故事/送礼）。
6. **收集图鉴**：收集感（功法图鉴/奇遇图鉴/成就碑）。

### 6.2 设计原则

- **禁止纯数值挂机**：所有成长入口均为真实代码验证（任务/修炼/考核/秘境/渡劫）。
- **自由目标**：玩家可自选「当前想做的事」，地图上每个入口都对应一类目标（修行/探索/修炼/任务/关系）。
- **即时反馈**：任何成长都有即时可见反馈（属性、文案、图鉴、关系称谓、世界状态）。

### 6.3 核心循环

```
探索（选择去哪）→ 遭遇（任务/奇遇/NPC）→ 编写代码 → 世界反馈（剧情/奖励/关系）
        ↑                                                    ↓
   解锁新探索 ←────────── 成长（境界/功法/贡献/好感）──────────┘
```

## 7. 技术方案

### 7.1 总体原则

- 不更换技术栈（Flask + 原生 JS + JSON 数据驱动）、不推翻架构。
- **沙箱 / 任务验证 / AI 师尊核心零改动**；全部为增量扩展。

### 7.2 数据结构变化

**新增数据文件：**

| 文件 | 内容 |
| --- | --- |
| `game/data/world.json` | 区域（region：名称/描述/解锁）、地点（location：名称/坐标/图标/所属区域/作用/解锁/连接）、区域间连通 |
| `game/data/story.json` | 主线章节（chapter：标题/剧情节点/触发条件/挂接任务）、支线（quest：任务堂发布）、奇遇（encounter：触发地点/概率/挑战模板） |
| `game/data/techniques.json` | 功法独立数据（id/name/knowledge/等级效果/前置/习得境界） |

**扩展现有数据：**

| 文件 | 扩展 |
| --- | --- |
| `game/data/npcs.json` | 每个 NPC 增加 `location`、`affinity` 起点、`relationship`（成长线文案） |
| `game/data/dialogues.json` | 节点增加 `require`（境界/任务/好感度/剧情标记）与 `affinity` 动作 |
| `game/data/tasks.json` | 任务 `kind` 增加 `practice`（演武场修炼）、`encounter`（奇遇）、`sect`（宗门任务） |

**玩家字段（全部带默认值，旧档自动兼容）：**

```
current_location: str = "cave"              # 当前所在地点
npc_affinity: dict[str, int]                # NPC 好感度
technique_progress: dict[str, int]          # 功法熟练度
technique_level: dict[str, int]             # 功法等级 1~4
story_flags: dict[str, str]                 # 剧情标记（章节/节点进度）
sect_contribution: int = 0                  # 宗门贡献
encounter_log: list[str]                    # 奇遇图鉴
```

### 7.3 地图系统方案

- 后端：`GET /api/world` 按玩家状态返回区域/地点/连接/可达性/解锁条件；`POST /api/world/move` 切换当前地点（校验解锁）。
- 前端：`screen-map` 从「卡片网格」重构为「区域-地点视图」（区域切换器 + 地点面板 + 连线），复用现有卡片组件与 `renderMap` 逻辑。
- 存档：`current_location` 持久化，读档回到原地点。

### 7.4 NPC 系统方案

- 数据扩展（location/affinity/relationship）。
- API：现有 `/api/npcs`、`/api/dialogues/<id>` 扩展返回好感度与 `require` 过滤后的可用节点；对话动作新增 `affinity`。
- 前端：地图地点卡片显示 NPC 头像；对话界面增加好感度条。

### 7.5 对话系统方案

- 节点树扩展：`require`（条件过滤，不满足则隐藏选项/节点）+ `affinity` 动作（进入节点加好感）。
- 动作幂等机制沿用（`npc_flags`），保证重复对话不重复刷奖励/好感。

### 7.6 存档变化

- `save.py` 版本 2 → 3；`Player.from_dict` 缺字段自动补默认（现有机制已支持，无需迁移逻辑）。
- 新增迁移测试：V0.1（version=1）、V0.2（version=2）存档读入不报错且新字段为默认值。

### 7.7 是否需要重构

- **不需要架构级重构**。
- 需要一次**前端地图视图的增量重构**（screen-map 从卡片网格 → 区域-地点视图），后端为纯增量（新数据 + 新 API + Player 字段）。
- 沙箱/验证/任务核心、存档原子写入、成就/道具/NPC 框架全部保留。

## 8. 开发顺序

| 阶段 | 内容 | 验收要点 |
| --- | --- | --- |
| A | 世界地图：`world.json` + `/api/world` + 前端区域-地点视图 + `current_location` | 3 区域 12+ 地点可达，解锁条件生效，旧存档可读 |
| B | NPC 在场与好感度：npcs/dialogues 扩展 + affinity + UI | 4 位核心 NPC 有地点与成长线，好感度可增减、可解锁节点 |
| C | 功法系统：`techniques.json` + 熟练度/等级 + 演武场修炼与考核 + 功法树 | 12 门功法可修炼升级，考核为真实代码验证 |
| D | 剧情系统：`story.json`（主线炼气篇 + 支线 + 奇遇 + 境界剧情） | 炼气篇主线闭环，奇遇 ≥8 种可触发可结算 |
| E | 长期成长闭环：图鉴/贡献/目标面板 + 数值平衡 | 六大动机均有落地入口与即时反馈 |
| F | 测试与发布：pytest 回归 + E2E 扩展 + 构建冒烟 | 全量测试绿；V0.2.5 功能零回归 |

> 每阶段结束后更新 DEVLOG；进入下一阶段前完成该阶段测试。

## 9. 风险分析

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 世界观包装过度，损害教学清晰度 | 学习质量下降（产品红线） | 教学块与叙事分离：教学块直白准确，叙事只负责动机与氛围；新增教学块测试 |
| 地图系统复杂度失控 | 开发周期膨胀 | 采用「区域-节点」图而非自由行走；禁止 3D；地点=卡片升级 |
| 剧情/数据文本膨胀 | 维护成本上升 | 模板化（奇遇复用挑战生成器）；story 分章维护 |
| 旧存档兼容问题 | 玩家进度丢失 | 字段默认值 + version 迁移测试（V0.1/V0.2 存档回归用例） |
| 数值膨胀 / 挂机感 | 破坏产品原则 | 所有成长绑定真实代码验证；数值保守并走平衡测试 |
| 随机挑战不可解 | 挫败感 | 复用「模板 + 参数白名单 + 沙箱自检」成熟机制 |
| 范围失控 | 无法交付 | 严格分阶段（A~F），每阶段验收通过才进入下一阶段 |
