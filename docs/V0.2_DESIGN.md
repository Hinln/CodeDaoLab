# 《码上飞升》V0.2 产品评审与设计方案

> 文档状态：V0.2 设计定稿（阶段一交付物）
> 评审人：首席开发工程师（兼任制作人/产品/架构/测试）
> 日期：2026-08-07

---

## 一、当前产品分析（V0.1 复盘）

### 1.1 已完成

- 12 境界（凡人→炼气一层~十层→筑基）、18 个任务（11 主线 + 4 Debug + 3 天劫）。
- 真实 Python 执行沙箱：`-I` 隔离子进程、超时/内存/模块隔离、随机 marker 防伪造。
- 输出精确比对与函数用例验证，**无关键词匹配**。
- JSON 存档（原子写入）、REST API、完整前端（CodeMirror 编辑器）。
- pytest 89 通过 + E2E 14 项通过 + zipapp 发行包冒烟验证。

### 1.2 产品定位判断

V0.1 的实质是**「剧情包装的任务关卡」**，属于高质量教学闭环，但尚不是完整的 RPG：

- 玩家只有一个「修为」数值，无角色成长曲线；
- 无 NPC、无对话、无世界互动；
- 任务完全线性，无随机性、无复玩价值；
- 无成就、无称号、无收集要素；
- 无 AI 引导（只有静态 hints 数组）；
- 境界体系止步筑基，缺乏长线目标。

### 1.3 结论

V0.2 的目标明确：**将 V0.1 升级为"修仙世界"，让 Python 成为世界规则而非任务背景板**。所有新增系统必须复用 V0.1 的「真实代码执行验证」内核，不允许降低学习质量换取游戏性。

## 二、游戏体验分析

### 2.1 体验优点（需保持）

- 每一关都要求真实写码，错误提交不推进，学习动机强；
- 世界观自洽（代码=法术、Bug=心魔、Debug=破境）；
- 反馈即时（输出、错误定位、中文提示）。

### 2.2 体验不足（V0.2 要解决的）

| 维度 | 现状 | 不足 |
| --- | --- | --- |
| 成长感 | 只有修为数字 | 缺属性曲线与可视化成长 |
| 陪伴感 | 无角色 | 缺师尊/同门，孤独通关 |
| 引导感 | 静态 hints | 卡关时无分级引导、无错误归因 |
| 自由度 | 线性推图 | 无支线、随机秘境、复玩 |
| 收集感 | 无 | 无成就/称号/道具/功法收藏 |
| 反馈 | 通过/失败弹窗 | 缺境界动画、连击、心魔惩罚等情绪反馈 |
| 长线 | 到筑基为止 | 缺更高境界目标 |

## 三、V0.2 设计总览

一句话目标：**让玩家在"修仙世界"里通过真实编码获得属性成长、NPC 陪伴、随机历练与成就收藏**。

### 3.1 世界观落位

- 修为 → 经验值；悟性 → 学习效率（影响提示分级节奏）；心境 → 状态系统（连续失败入魔）；Debug 经验 → 除魔专长。
- 新境界链：凡人 → 炼气 → 筑基 → **金丹 → 元婴 → 化神 → 炼虚 → 合体 → 大乘 → 渡劫**（V0.2 先实现前四个可用境界的数据与内容框架，突破全部走代码挑战）。
- 突破 = 渡劫：每个大境界突破前有「渡劫试炼」（真实代码挑战），不通过不得突破。

### 3.2 八大系统设计

#### ① 角色系统
- 道号、灵根（保留 V0.1）、性别（可选，纯风味）。
- 新增：境界、修为、悟性、心境、Debug 经验、称号、道具背包、成就列表、已学功法（藏经阁解锁记录）。
- 灵根影响：金/木/水/火/土 → 给不同属性加成（如土灵根初始心境更高），纯数值风味，不改变任务。

#### ② 属性系统
| 属性 | 作用 | 获取/变化 |
| --- | --- | --- |
| 修为 | 境界门槛与等级 | 任务/秘境/成就奖励 |
| 悟性 | 控制 AI 师尊提示分级节奏（悟性高→更快给更细线索） | 首次独立解题、成就奖励 |
| 心境 | 失败惩罚机制（连续提交失败 → 心境下降；心境低时 AI 师尊更多鼓励） | 通过任务恢复、失败递减 |
| Debug 经验 | 炼丹房专长，解锁高级 Debug 提示 | 完成 Debug 任务 |

#### ③ 境界系统
- 数据驱动境界链（V0.1 的 12 境界为「炼气期」细分；V0.2 将境界抽象为 **大境界（realm）+ 小境界（stage）** 两层）。
- 兼容：V0.1 的 qi1~qi10 映射为炼气期 stage；foundation 映射为筑基期 stage 1。
- 突破必须通过代码挑战：突破前自动生成「突破试炼」任务（复用沙箱验证）。

#### ④ NPC 系统
- 数据驱动 `npcs.json`：id、姓名、称号、头像（emoji/文字）、定位地点、对话、任务关联。
- V0.2 NPC：青玄子（AI 师尊）、藏经阁长老（功法）、炼丹房执事（Debug）、秘境引路人（秘境入口）、同门弟子（闲聊/支线）。

#### ⑤ 对话系统
- 数据驱动 `dialogues.json`：节点式对话（node_id → text → options → goto / action），无分支复杂度爆炸。
- 对话可触发动作：解锁任务、给奖励、给提示、进秘境。
- 前端对话面板复用弹窗组件，支持打字机效果（轻量实现）。

#### ⑥ 任务系统（数据驱动升级）
- 任务类型扩展：`main` / `debug` / `wave` / `branch`（支线）/ `trial`（突破试炼）/ `secret`（秘境）。
- 任务数据增加：前置条件（解锁表达式）、NPC 关联、奖励结构（修为/悟性/道具/成就）。
- 保留 V0.1 的 `check` 验证结构，**验证引擎不动**。

#### ⑦ 秘境系统
- 三个秘境：青云秘境（炼气~筑基）、万象幻境（金丹~元婴）、代码天宫（高阶预留）。
- 随机生成：从「挑战模板池」按境界筛选，参数随机化（数值/用例/题干），每次进入生成新任务。
- 所有秘境任务仍走真实沙箱验证（模板产出标准 `check` 结构）。
- 奖励：修为、悟性、Debug 经验、道具（丹药：一次性提示牌）、成就。

#### ⑧ 成就系统
- 数据驱动 `achievements.json`：id、名称、描述、触发条件（事件计数）、奖励、称号。
- 事件总线：任务完成、Debug 完成、首次突破、连续通过、秘境通关、登录（续玩）等。
- 前端成就面板 + 获得弹窗。

### 3.3 AI 师尊系统设计（阶段三细化）

- 独立接口层 `game/ai/`：`TutorProvider` 抽象（`guidance(player, context) -> str`）。
- 默认实现：**本地规则引擎**（无需 API key、离线可用），解析 `RunResult` 与任务数据生成分级提示。
- 可选实现：OpenAI 兼容 HTTP 接口（配置 base_url/model/api_key 即启用，接口不变）。
- 提示等级：L1 方向提示 → L2 范围缩小 → L3 明确线索 → L4 查看答案。
- 错误归因：语法/运行/超时/内存/输出不符 → 每种错误有专属引导话术模板。
- 境界适配：入门境界用白话教学腔，高阶境界用修仙黑话。
- 铁律：不直接给答案（L4 才给，且鼓励先自查）。

### 3.4 Python 内容扩充设计（阶段五细化）

- 新知识点：字符串、文件操作、模块、异常处理、面向对象基础。
- 每个知识点 7 要素：剧情 → 功法介绍 → 教学 → 示例 → 任务 → Debug 挑战 → 综合试炼。
- 对应境界落位：金丹（字符串/异常）、元婴（模块/文件）、化神（OOP 基础），与境界链联动。
- V0.2 至少完整实现：字符串、异常处理、模块、文件操作、OOP 基础五个知识点的「教学 + 任务 + Debug + 试炼」。

## 四、技术架构设计（阶段二细化）

### 4.1 数据文件规划（全部数据驱动）

| 文件 | 内容 |
| --- | --- |
| `game/data/curriculum.json` | 境界链（大境界+小境界）、教学 |
| `game/data/tasks.json` | 全部任务（含新类型） |
| `game/data/npcs.json` | NPC 定义与地点 |
| `game/data/dialogues.json` | 对话树 |
| `game/data/achievements.json` | 成就与称号 |
| `game/data/secret_realms.json` | 秘境定义与挑战模板池 |
| `game/data/items.json` | 道具定义（丹药等） |

### 4.2 存档 v2（向后兼容）

- 槽位升级：`saves/{slot}.json` 多槽位（V0.1 的 default 槽保留）。
- 结构：`{version: 2, player: {...}, meta}`；加载时若 version=1 自动迁移（补默认属性）。
- 新增字段：attributes（悟性/心境/debug_exp）、achievements、items、secret_realm_log、npc_state。

### 4.3 API 扩展

- `GET /api/achievements`、`POST /api/achievements/claim`（领取奖励）
- `GET /api/npcs`、`GET /api/dialogues/<npc_id>`、`POST /api/dialogues/<npc_id>/choose`（对话推进）
- `GET /api/secret-realms`、`POST /api/secret-realms/<id>/enter`、`POST /api/secret-realms/<id>/submit`
- `POST /api/ai/guidance`（AI 师尊，返回分级提示）
- `GET /api/slots`、`POST /api/game/new?slot=`、`POST /api/game/load`（多槽位）

### 4.4 前端结构

- 洞府地图新增地点卡片：藏经阁、秘境入口、NPC（师尊洞府）。
- 新增页面/面板：成就面板、属性面板、对话面板、秘境面板、AI 师尊面板（任务页内嵌）。
- 全部沿用现有 CSS 体系（修仙风深色主题）。

## 五、风险与对策

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| AI 接口外部依赖导致不可用 | 高 | 默认本地规则引擎，外部模型仅作可选增强 |
| 随机秘境任务不可验证/不可解 | 高 | 模板 + 参数白名单随机化；产出前用沙箱跑参考答案自检 |
| 大规模改动破坏 V0.1 内容 | 高 | 存档迁移、数据向后兼容、每阶段 pytest 回归 + E2E |
| 对话树复杂度失控 | 中 | 节点式结构 + 动作指令白名单 |
| 境界两层结构复杂化 | 中 | realm/stage 查询函数统一封装，前端只读展示 |

## 七、结论

V0.2 在保持「真实代码验证」内核的前提下，补齐 RPG 的成长、陪伴、随机与收集四大支柱，使《码上飞升》从教学闭环升级为可长期游玩的 Python 修仙 RPG。全部新增功能均数据驱动、真实执行、可测试。
