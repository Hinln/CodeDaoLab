# CodeDaoLab Godot Edition V0.2 产品体验评审

评审日期：2026-08-08  
评审版本：v0.1.0  
评审范围：创建角色 -> 青云宗探索 -> NPC 交互 -> 三门功法 -> Python 代码试炼 -> Bug 妖 -> 引气入体 -> 章节结束

## 1. 评审结论

v0.1.0 已经是一个可运行、可通关、规则闭环稳定的垂直切片。它最有价值的部分，是把 Python 语法错误、输出结果和修仙叙事真正连接到同一条成长主线中，而不是在 RPG 外壳里附加一道普通编程题。

当前最大差距不是“内容太少”，而是关键行为缺少足够的情境、反馈和情感关系。玩家能够完成任务，但容易感觉自己在按顺序操作界面，而不是以一名新弟子的身份进入宗门、修习术法并完成突破。V0.2 应当停止横向扩张，集中把第一章从“功能演示”提升为“有记忆点的游戏章节”。

## 2. 完整体验观察

### 2.1 启动与角色创建

- 标题图已经建立青云、山门和修仙基调，项目身份明确。
- 道号输入能形成最低限度的角色归属感。
- 创建选择目前对后续体验影响很弱，玩家无法从角色页预判自己的修炼风格。
- 缺少“我是谁、为何来到青云宗、第一步要做什么”的短叙事钩子。

### 2.2 进入宗门与探索

- 五处地点让第一章具备真实空间，而不是纯菜单跳转。
- 移动、相机和地点提示构成了可玩的探索基础。
- 地图的功能分区清楚，但环境变化、可观察物和声音层次不足，探索主要承担赶路功能。
- 新玩家容易依赖任务文字猜测下一位 NPC 或地点，世界本身没有充分承担引导职责。

### 2.3 NPC 与剧情

- 三名 NPC 的职责分工清晰，能够稳定推动任务链。
- 条件对话、好感度和持久化为长期关系系统留下了正确接口。
- NPC 目前更像任务节点：缺少立绘、表情、动作反应、主动问候和对玩家既往行为的自然回忆。
- 对话选择会改变状态，但玩家对“关系发生了什么变化”的感知较弱。

### 2.4 功法与代码修炼

- 真言诀、变量吐纳诀、循环周天诀把 Python 概念翻译为修仙术语，是当前最鲜明的产品优势。
- 三次试炼的难度和知识顺序合理，真实 Python 判题保证了学习结果可信。
- CodeEdit 仍然容易被体验为开发工具输入框；从落笔、运转到结果显示之间缺少施法过程。
- 成功主要以文本、数值和解锁反馈呈现，失败也主要是错误信息，灵力、心境和功法掌握度没有被视觉化。
- L1-L4 提示逻辑完整，但师尊的存在感集中在“答错之后”，尚未形成同行伙伴感。

### 2.5 Bug 妖战斗

- 三阶段分别对应语法、逻辑和命名错误，战斗概念与编程学习结合自然。
- 错误会消耗心境，修正后击破阶段，规则清楚且可验证。
- 三阶段的交互节奏相近，Boss 的形态、攻击、压迫感与代码修正之间缺少强烈联动。
- 玩家是在修三段代码，但还没有充分感到自己在识破招式、反制妖术。

### 2.6 突破与章节结束

- 击败 Boss 后回到师尊处引气入体，形成了明确的章节闭环。
- 境界、修为、功法和任务状态均可保存恢复，完成感不会因退出而丢失。
- 突破演出、角色变化和世界回应偏轻，高潮与前面普通任务的表现层级差异不够大。
- 章节结算能够说明结果，但还需要让 NPC、环境和能力共同证明玩家已经成长。

## 3. 当前版本优点

1. **核心概念独特**：代码不是外挂题库，而是功法、战斗和境界成长的共同语言。
2. **第一章闭环完整**：创建、探索、学习、战斗、突破、结算均已连通。
3. **学习顺序可靠**：输出、变量、循环与三类 Bug 组成清晰的认知阶梯。
4. **真实执行可信**：Python 沙箱验证真实代码，避免“选答案式编程”的虚假感。
5. **系统基础稳定**：任务、对话、关系、功法、导师、存档均为数据驱动并有自动化覆盖。
6. **范围控制良好**：五处地点、三名 NPC、三门功法足以支撑第一章，没有被开放世界目标拖垮。

## 4. 最大问题

### 4.1 最大产品问题：玩家在完成流程，而不是经历修炼

玩法规则已经成立，但输入代码前后的情绪曲线太平。缺少蓄势、施法、命中、反噬、领悟和世界回应，导致最独特的“代码修仙”卖点没有在表现层兑现。

### 4.2 最大新手问题：下一步可做，但不总是自然可知

任务文字能够给出目标，但地点、人物和可交互物的空间引导不足。首次进入的玩家可能理解操作，却不理解为什么要去、该往哪里去，以及当前行为与修炼目标的关系。

### 4.3 最大情感问题：师尊和 NPC 是系统，不是关系

已有好感和提示能力，却缺少立绘表情、历史回忆、主动关怀和阶段性评价。玩家对 NPC 的记忆容易停留在“谁给哪个任务”。

### 4.4 最大成长问题：角色选择与功法成长缺少可见差异

道号之外的身份塑造有限，功法学会后缺少清晰的分支、熟练过程和表现升级。玩家完成一章后，角色仍较难形成“这是我的修士”的独特感。

## 5. 优先级问题

### P0：直接影响第一章理解和核心卖点

| 问题 | 玩家后果 | V0.2 处理方向 |
| --- | --- | --- |
| 目标、NPC 和地点引导不足 | 卡住、乱走、依赖试错 | 当前目标卡、世界内标记、距离提示、完成后的下一步指向 |
| 写代码不像施法 | 核心卖点退化为题库界面 | 建立“起式 -> 运转 -> 显化 -> 命中/反噬”反馈链 |
| 失败反馈与导师出现割裂 | 新手把错误理解为惩罚 | 错误定位、心境反馈、师尊分级回应在同一结果面板呈现 |
| Python 环境异常缺乏玩家化解释 | 无法继续主线 | 启动预检、明确修复说明、重试入口，不把环境错误伪装成代码错误 |
| 突破高潮表现不足 | 第一章完成感弱 | 独立演出、音画层升级、NPC 回应和能力变化 |

### P1：决定玩家是否愿意记住角色与世界

| 问题 | 玩家后果 | V0.2 处理方向 |
| --- | --- | --- |
| 灵根和身份缺少意义 | 创建页成为形式 | 小范围初始差异、专属台词和成长倾向 |
| 地图缺少氛围层 | 探索像移动菜单 | 天气、环境音、局部动态、观察点和一次性发现 |

| 功法成长不可见 | 学会后缺少期待 | 三条轻量技能枝、熟练度节点和升级演出 |
| Boss 三阶段表现重复 | 战斗后半段疲劳 | 阶段形态、攻击语义、场景变化和不同破招反馈 |

### P2：提高复玩、舒适度和完成品质

| 问题 | 玩家后果 | V0.2 处理方向 |
| --- | --- | --- |
| 可选探索内容少 | 路线没有惊喜 | 小型观察点、藏书、灵气残响和一次性支线对话 |

| 二周目差异不足 | 复玩动力弱 | 灵根/身份专属开场与一处差异化解法，不扩展新地图 |

## 6. 玩家体验风险

1. **概念错位风险**：如果代码面板长期保持工具感，玩家会把产品理解成“披着修仙皮的练习网站”。
2. **新手流失风险**：地点引导与代码错误同时造成认知压力时，零基础玩家可能在第一次术法前退出。
3. **高手无聊风险**：有经验的 Python 玩家若只能顺序输入固定答案，会缺少表达空间。
4. **惩罚误读风险**：心境扣除若没有温和解释，可能让学习失败带来羞耻感，而不是探索感。
5. **关系落空风险**：宣传 AI 师尊但只在错误时给提示，会造成伙伴承诺与实际体验不一致。
6. **环境依赖风险**：发布包依赖系统 Python；缺少预检时，安装问题会被误认为游戏 Bug。
7. **范围反弹风险**：同时做大地图、复杂装备或更多境界会稀释第一章打磨，必须继续禁止横向膨胀。

## 7. V0.2 成功标准建议

- 新玩家进入宗门后 30 秒内能说出当前目标和目标地点。
- 第一次代码成功时，即使隐藏文字，玩家也能从动画和声音判断“施法成功”。
- 第一次代码失败后，玩家能分清代码错误、环境错误和挑战目标不符。
- 通关后玩家能说出至少一名 NPC 的性格，而不仅是其任务功能。
- 灵根或身份至少影响一段对话、一个反馈和一个轻量成长选择。
- 突破演出的表现层级明显高于普通任务完成。
- 不增加大地图、联机、复杂装备和商业系统。
