# CodeDaoLab Godot Edition V0.2 体验设计

版本定位：第一章体验强化版  
设计目标：让玩家感到“我在青云宗以代码修炼”，而不是“我在地图里完成编程题”

## 1. 设计原则

1. **代码即法术**：所有代码输入、执行、成功和失败都必须有修仙世界内的解释与反馈。
2. **成长必须可见**：角色、功法、关系和场景至少有一项可见变化证明玩家成长。
3. **引导存在于世界**：优先通过人物、地标、光线、声音和空间标记引导，而不是堆叠说明文字。
4. **失败是师徒互动**：错误应触发诊断、鼓励和策略升级，不制造羞耻或无意义惩罚。
5. **纵向打磨第一章**：复用五处地点、三名 NPC、三门功法和一个 Boss，不扩大世界规模。

## 2. 目标体验节奏

建议单次第一章时长：25-35 分钟。

| 阶段 | 时长 | 情绪目标 | 核心体验 |
| --- | ---: | --- | --- |
| 身份建立 | 3-5 分钟 | 好奇、归属 | 道号、灵根、身份、师尊初见 |
| 宗门初探 | 5-7 分钟 | 探索、理解 | 地标引导、环境观察、NPC 记忆点 |
| 三诀入门 | 8-12 分钟 | 领悟、掌控 | 代码施法、导师陪伴、技能成长 |
| Bug 妖 | 6-8 分钟 | 压力、反制 | 三种错误具象化、阶段破招 |
| 引气入体 | 2-3 分钟 | 释放、成就 | 突破演出、世界回应、章节回顾 |

## 3. 角色体验

### 3.1 创建内容

- **道号**：自由输入，保留现有能力；NPC 在关键对话中直接称呼。
- **灵根**：金、木、水、火、土五选一，主要提供视觉主题、师尊评价和轻量倾向，不锁死内容。
- **身份**：书院学童、山野散修、工坊学徒三选一，决定一段背景文案、一句专属 NPC 对话和一个初始小优势。
- **成长预览**：选择时用一句世界观描述加三枚图标展示影响，避免玩家盲选。

### 3.2 灵根差异

| 灵根 | 表现主题 | 第一章轻量差异 |
| --- | --- | --- |
| 金 | 白金、锐利符线 | Bug 妖首次命中反馈更强，师尊强调精确 |
| 木 | 青绿、生长纹 | 首次失败少损失 1 点心境，云游子有专属评价 |
| 水 | 靛蓝、流动轨迹 | 提示层级切换更平滑，玄机长老强调拆解思路 |
| 火 | 赤金、爆发粒子 | 首次成功施法演出强化，青玄子评价更直接 |
| 土 | 赭黄、稳定阵纹 | 连续失败时获得一次稳定心境反馈 |

这些差异不改变题目答案、不形成强弱排行，只塑造角色风格。

### 3.3 身份差异

| 身份 | 叙事定位 | 初始优势 |
| --- | --- | --- |
| 书院学童 | 熟悉文字，不懂灵力 | 第一次语法提示提前一级 |
| 山野散修 | 熟悉山路，缺少系统训练 | 首次进入地点获得额外观察描述 |
| 工坊学徒 | 擅长拆装和查错 | Bug 妖第一阶段显示一个结构线索 |

### 3.4 成长可见化

- 角色脚下阵纹随掌握功法从无到三环。
- HUD 显示“凡身 -> 感气 -> 引气入体”的阶段，而不仅显示修为数字。
- 章节结束展示道号、灵根、身份、三诀掌握和师尊评语。

## 4. 世界体验

### 4.1 地图氛围

保留现有五处地点，不增加大地图。每处增加一个主色、环境动态和辨识声音：

| 地点 | 视觉锚点 | 动态 | 声音锚点 |
| --- | --- | --- | --- |
| 山门 | 石阶、云海、宗门旗 | 云层缓移、旗帜摆动 | 风声、远钟 |
| 弟子居 | 木廊、灯笼、竹影 | 灯火呼吸、竹叶飘落 | 木鱼、脚步回响 |
| 藏经阁 | 高窗、卷轴、金色尘埃 | 书页翻动、尘光漂浮 | 纸页、低沉室内声 |
| 演武场 | 阵纹、木桩、兵器架 | 阵纹脉冲、弟子剪影 | 破风、远处喝声 |
| 后山 | 古树、裂石、雾谷 | 雾带、虫鸣骤停 | 溪流、低频妖气 |

### 4.2 天气与时间

- 第一章只设计三种受剧情控制的氛围状态：清晨薄雾、午后流云、Boss 前阴风。
- 天气服务叙事节奏，不制作随机天气模拟器。
- 击败 Boss 后恢复清朗并增强环境亮度，作为世界回应。

### 4.3 探索内容

每个地点放置一个“灵息观察点”，首次调查获得一句世界观、一点小奖励或 NPC 话题。观察点不影响主线，不扩展为采集或复杂支线系统。

- 山门：残缺门规碑。
- 弟子居：前代弟子的练功刻痕。
- 藏经阁：自动翻页的无字残卷。
- 演武场：失效的旧阵眼。
- 后山：被 Bug 妖污染的灵脉。

### 4.4 引导系统

- HUD 同时显示“当前目标”和“目标地点”。
- 世界内使用低饱和灵光、路牌和 NPC 头顶符印，不使用持续闪烁箭头。
- 接近目标时显示距离与交互键；走错较久后由师尊传音提供方向。
- 每完成一步，仅突出一个下一目标，避免同时开放多个噪声标记。

## 5. NPC 体验

### 5.1 立绘与表情

三名核心 NPC 各配置半身立绘和四种基础表情：平静、欣慰、疑惑、严肃。对话框根据语义切换表情，关键句增加轻微呼吸、侧移或震动，不制作高成本骨骼动画。

### 5.2 性格定位

| NPC | 核心性格 | 与玩家的关系作用 |
| --- | --- | --- |
| 青玄子 | 克制、可靠、偶尔冷幽默 | 主师尊，负责看见玩家成长并提供安全感 |
| 玄机长老 | 严谨、惜字、尊重推理 | 让玩家感到思考本身有价值 |
| 云游子 | 松弛、好奇、擅长换角度 | 缓解失败压力，提供非标准观察 |

### 5.3 记忆模型

每名 NPC 保存少量结构化记忆，不记录自由文本聊天：

- 初次见面是否完成。
- 玩家灵根与身份。
- 最近一次挑战结果。
- 连续失败次数区间。
- 玩家是否主动探索其关联观察点。
- 当前关系阶段。

记忆通过后续称呼、问候和评价显现。例如玩家连续失败后再次见青玄子，他先询问心境，而不是重复任务台词。

### 5.4 长期关系

关系分为“初识、认可、信任”三阶。V0.2 第一章最多达到认可，变化来源包括认真完成试炼、主动观察世界和对话选择。关系不解锁数值强装备，只解锁台词、提示语气和章节评语。

## 6. 功法体验

### 6.1 轻量技能树

三门功法形成一条主干，每门功法提供三个可见节点：

1. **入门**：完成代码试炼，获得基础施法表现。
2. **运转**：在后续挑战中正确使用对应概念，阵纹增强。
3. **小成**：完成一次关联心魔挑战，解锁外观变化和师尊评价。

节点主要表达掌握过程，不在 V0.2 建立复杂战斗数值树。

### 6.2 修炼反馈

- 学会：功法卷轴展开，字符转化为阵纹。
- 运转：HUD 灵力沿经脉槽流动，代码行依次点亮。
- 升级：角色阵纹增加一环，场景短暂响应。
- 查看：功法面板展示概念、已掌握证据、下一领悟条件，而不是只有名称和等级。

## 7. 代码修炼：让写代码像施法

### 7.1 完整施法链

1. **观题**：挑战目标以师门问题和预期异象呈现。
2. **落笔**：输入字符时产生克制的墨光轨迹；括号、关键字和变量分别对应符文颜色。
3. **起式**：点击“运转周天”后锁定编辑，代码行从上到下依次注入灵力。
4. **显化**：`print` 输出化为场景中的光字或灵息波纹。
5. **命中**：正确结果形成术法特效并作用于目标。
6. **反噬**：语法、运行、超时、输出错误呈现不同异象，再由师尊解释。

### 7.2 错误类型表现

| 错误 | 世界内表现 | 产品信息 |
| --- | --- | --- |
| 语法错误 | 符文断裂，定位行出现裂纹 | 显示行号与可理解描述 |
| 运行错误 | 灵力运转到某行后反冲 | 显示异常类型和触发位置 |
| 超时 | 阵纹循环加速后冻结 | 说明可能存在无法结束的循环 |
| 输出不符 | 法术成功显化但未命中目标 | 并排显示预期异象和实际输出 |
| 环境异常 | 阵法未启动，显示外部法器故障 | 给出 Python 检查、重试和诊断入口 |

### 7.3 心魔挑战

- 每门功法小成前提供一个 60-90 秒的可选心魔挑战。
- 心魔不是限时手速题，而是移除一层提示或加入一个干扰错误。
- 失败不倒退主线，只影响小成评价；师尊会根据失败方式提供复盘。
- 有经验玩家可直接挑战，初学者可在完成普通练习后进入。

### 7.4 不同水平玩家

- 初学者获得目标拆解、运行预览和分级提示。
- 熟练玩家可隐藏模板、使用自由变量名，并获得“清简解”评价。
- 判题继续基于行为结果，不要求固定字符串答案。

## 8. AI 师尊：从提示工具升级为伙伴

### 8.1 伙伴职责

- **入门前**：解释此术法为何值得学。
- **落笔时**：保持安静，只在停顿过久时提供可忽略的传音。
- **失败后**：先识别错误类型，再结合历史给一层恰当提示。
- **成功后**：指出玩家真正掌握的概念，而不是泛泛夸奖。
- **重逢时**：引用结构化记忆，表现持续陪伴。
- **章节末**：生成基于固定模板和真实状态的个性化评语。

### 8.2 个性化规则

- 连续语法错误：降低术语密度，先检查结构。
- 多次输出不符：引导比较“预期”和“实际”，不直接给完整答案。
- 高悟性：更早提出抽象规律和替代写法。
- 低心境：先稳定情绪，再给一个最小可行动步骤。
- 连续独立成功：减少主动提示，转为追问和挑战。

### 8.3 记忆边界

- 只保存玩法需要的结构化状态，不保存不必要的自由输入历史。
- 玩家可在设置中查看并清除师尊记忆。
- AI 服务不可用时，现有本地 L1-L4 规则必须完整接管主线，不阻塞通关。

## 9. Boss 体验升级

| 阶段 | 妖术主题 | 视觉变化 | 破招体验 |
| --- | --- | --- | --- |
| 一阶段 | 断句噬符，语法混乱 | 身体由破碎括号与残符组成 | 修复语法后符链闭合并斩断一肢 |
| 二阶段 | 逆转因果，逻辑错误 | 场景方向与光流反转 | 正确循环让灵流归位并击破护盾 |
| 三阶段 | 夺名换形，变量错乱 | 名称符牌不断互换 | 统一变量后锁定真名并完成终击 |

每阶段失败只扣除少量心境，并立即提供与攻击语义一致的反馈。阶段切换使用短演出，不插入长过场打断思考。

## 10. 突破与章节结算

### 10.1 引气入体演出

- 场景降低环境声，只保留呼吸与灵力脉冲。
- 三门功法阵纹依次出现并汇入角色。
- 灵根决定主色和粒子形态。
- 玩家主动按一次“引气入体”，而不是纯自动播放。
- 成功后音乐、天空亮度、角色阵纹和 HUD 境界同时变化。

### 10.2 世界回应

- 青玄子给出基于失败次数与独立完成度的评语。
- 玄机长老评价玩家最稳定的思维方式。
- 云游子回应玩家是否调查过后山灵脉。
- 后山妖气消失，相关观察点文案变化。

### 10.3 章节回顾

结算页显示：

- 道号、灵根、身份和新境界。
- 三门功法掌握节点。
- 最困难的一次挑战和最终突破方式。
- 三名 NPC 当前关系。
- 一句师尊个性化寄语。
- 下一章只给叙事钩子，不提前承诺大型系统。

## 11. 界面与可访问性

- 代码字体、剧情字体和数值字体建立明确层级。
- 代码区保持高对比度，符文特效不能遮挡字符。
- 所有动画提供“减少动态效果”选项。
- 镜头震动、打字音、环境音分别可调。
- 颜色之外同时使用形状和文字区分成功、警告和错误。
- 中文输入法组合输入期间不触发快捷键或自动提交。

## 12. V0.2 实施顺序建议

### V0.2-A：P0 可理解性

- 当前目标与世界内导航。
- Python 环境预检与玩家化错误。
- 统一代码结果、导师和心境反馈面板。

### V0.2-B：核心施法感

- 代码运转动画、输出显化、成功与四类失败反馈。
- 三门功法学习与升级演出。
- Bug 妖三阶段差异化表现。

### V0.2-C：角色与关系

- 灵根、身份和创建预览。
- NPC 立绘表情、结构化记忆与关系阶段。
- 师尊重逢、成功和章节评语。

### V0.2-D：世界与收口

- 三种剧情氛围、五处声音锚点、五个观察点。
- 引气入体演出、世界回应和章节回顾。
- 可访问性设置与完整新玩家测试。

每个子阶段都应保持第一章可完整通关，并继续运行现有 92 项自动化检查。

## 13. V0.2 验收指标

| 目标 | 验收方式 |
| --- | --- |
| 新手理解目标 | 5 名未接触项目的玩家中，至少 4 名无需外部解释找到首个 NPC |
| 代码像施法 | 首次成功时，至少 4/5 玩家主动描述为施法、运功或攻击反馈 |
| 错误可恢复 | 所有测试玩家能在首次错误后说出下一步可尝试动作 |
| NPC 有记忆点 | 通关后至少能描述一名 NPC 的性格与一次回应 |
| 角色有差异 | 两种灵根/身份组合在开场、施法和结算中均有可见差异 |
| 高潮成立 | 突破演出的主观强度明显高于普通任务完成 |
| 稳定性保持 | 92 项现有 Godot 检查全部通过，Web Edition 回归不下降 |

## 14. 明确不做

- MMO、联机和多人社交。
- 开放世界或大规模地图扩建。
- 复杂装备、掉落、锻造和词条系统。
- 商城、付费点或商业化系统。
- 第一章之外的大量境界和剧情内容。
- 为追求“AI 感”而让在线模型成为主线通关硬依赖。
