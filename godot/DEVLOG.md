# 《码上飞升：青云宗篇》Godot 开发日志

## 项目约束

- 引擎：Godot 4.x，当前开发验证版本为 4.7.1-stable。
- 形态：2.5D 俯视角单机 RPG Demo。
- 范围：青云宗第一章，不修改 Web Edition 核心代码与数据格式。
- 流程：实现 → 测试 → 修复 → 更新日志 → 提交 → 下一阶段。

## G0 · 项目初始化与技术架构（2026-08-08）

### 完成内容

- 建立独立 `godot/` 项目、目录结构、项目图标和运行说明。
- 建立 `EventBus`、`DataRepository`、`GameState`、`SaveManager`、`SceneRouter` 五个 Autoload。
- 建立深青水墨风标题场景及新游戏、继续、退出入口。
- 建立首章世界、NPC、对话、功法、挑战和剧情 JSON 骨架。
- 建立独立 `user://saves/` 存档边界，不接触 Web Edition 存档。
- 使用官方 Godot 4.7.1 Windows 便携版作为本地开发工具，工具位于被忽略的 `.tools/`。

### 技术决策

- 世界逻辑使用 Godot 2D 节点，通过 Y 排序、遮挡、阴影和视差形成 2.5D 观感。
- 游戏状态与 UI 使用信号解耦；数据使用稳定 ID 的 JSON 驱动。
- 玩家 Python 代码不由 GDScript 判定，后续通过独立桥接进程真实隔离执行。
- 原型阶段使用程序化占位资源，玩法闭环通过后再集中替换美术。

### 测试结果

- `Godot --headless --editor --path godot --quit`：通过，项目扫描、Autoload 注册与资源导入无错误。
- `Godot --headless --path godot --quit-after 3`：通过，主场景启动并输出版本标识。

### 当前问题

- 本机原先未安装 Godot，已在 `.tools/godot/` 配置便携版，不影响仓库和系统环境。
- 当前仅为可运行工程骨架，角色创建和世界探索将在 G1 实现。

### 下一步

- G1：实现角色创建、玩家控制、摄像机、青云宗五处地点、交互提示与位置存档。

## G1 · 角色与青云宗世界（2026-08-08）

### 完成内容

- 新增道号与五行灵根角色创建界面，包含长度校验与灵根说明。
- 新增 `CharacterBody2D` 玩家、WASD/方向键移动、E 键交互与 Camera2D 平滑跟随。
- 新增程序化 2.5D 青云宗地图：山门、弟子洞府、藏经阁、演武场、后山入口。
- 新增地点距离检测、HUD 交互提示、地点说明、当前任务和角色属性显示。
- 标题、新建角色、世界、返回标题流程已串联；返回标题前自动保存。
- 存档支持测试路径覆盖，验证时不会污染真实玩家存档。

### 技术决策

- 第一章地图保持单场景连续探索，地点用稳定 ID 和 JSON 坐标生成。
- 玩家位置在世界运行时同步到 `GameState`，主动保存时写入 `user://saves/`。
- 使用程序化山体、道路、建筑和角色剪影形成 2.5D 占位视觉，避免美术阻塞玩法。

### 问题与修复

- Godot 4.7 新增原生 `CanvasItem.draw_ellipse()`，与自定义绘制函数重名并导致解析失败；已改名为 `_draw_oval()`。
- JSON 字段读取推断为 `Variant` 的警告在编辑器中按错误处理；已显式声明 `Dictionary`。
- 首次组合测试因脚本解析失败未进入测试场景而挂起；拆分导入与场景测试后定位并修复。

### 测试结果

- 编辑器无头导入：通过，无脚本解析错误。
- G1 冒烟：9 / 9 通过，包括五地点、场景实例化、出生点、存档与坐标恢复。
- 正式主场景无头启动：通过。

### 下一步

- G2：将青玄子、玄机长老、云游子作为世界实体加入对应地点，实现对话、任务动作与第一章推进。

## G2 · NPC、对话与第一章任务（2026-08-08）

### 完成内容

- 青玄子、玄机长老、云游子作为 2.5D 世界实体生成在洞府、藏经阁和后山入口。
- 靠近 NPC 后 HUD 显示交谈提示，E 键打开对话，交谈期间锁定玩家移动。
- 新增数据驱动 `DialogueManager`：节点跳转、任务/标记条件过滤、选项渲染和结束恢复。
- 新增 `QuestManager`：读取第一章任务节点并执行固定白名单动作。
- 对话动作支持剧情标记、当前任务、NPC 好感和提示事件。
- 青玄子首次对话将“踏入山门”推进至“真言初成”，授予 5 点好感并记录拜师标记。
- NPC 好感、剧情标记和当前任务进入独立存档并可恢复。

### 技术决策

- NPC 视觉继续使用统一比例的程序化剪影，颜色区分角色但保持同一美术语言。
- JSON 仅声明动作类型与参数，不执行脚本、表达式或任意方法。
- 对话选项在每次显示时根据当前任务和剧情标记过滤，避免 UI 展示不可执行分支。

### 测试结果

- G2 冒烟：14 / 14 通过，包括 NPC 地点、实体生成、条件对话、任务推进、好感与存档恢复。

### 当前问题

- 对话 UI 使用占位主题，统一 Theme 将在 G5 优化。

### 下一步

## G3 · 功法与真实 Python 修炼（2026-08-08）

### 完成内容

- 新增真言诀、变量吐纳诀、循环周天诀三门第一章功法。
- 新增 `CodeEdit` 试炼界面，支持运行推演、提交验证、标准输出、语法/运行错误和奖励反馈。
- 新增 Godot `PythonBridge`，后台线程调用独立一次性 JSON 桥接进程。
- 新增 `python_bridge/runner.py`，复用仓库现有隔离沙箱执行玩家代码，Godot 不做关键词判断。
- 正确提交按顺序推进真言、变量、循环三段任务；错误提交不推进。
- 新增 `TechniqueManager`，处理功法习得、熟练度、修为、首次结算与重复奖励保护。
- 演武场按当前任务开启真言/循环试炼，玄机长老对话开启变量试炼。
- 新增功法面板，显示已习得状态、入门等级、熟练度和对应 Python 知识点。

### 技术决策

- Python 请求与响应使用 `user://python_bridge/` 临时 JSON 文件，参数不拼接进命令字符串。
- Python 执行设置 5 秒超时、256 MB 内存限制，并继承现有危险模块和临时目录隔离。
- 第一章挑战采用标准输出精确比对；后续函数题可在同一桥接协议增加测试用例验证。
- GDScript 使用后台线程等待 Python，避免代码运行期间阻塞渲染主线程。

### 测试结果

- 编辑器无头导入：通过。
- G1 回归：9 / 9 通过。
- G2 回归：14 / 14 通过。
- G3 冒烟：16 / 16 通过，包括正确/错误/语法错误、三功法推进、重复奖励保护和存档恢复。

### 当前问题

- 源码运行依赖系统 Python 3.10+；最终发布阶段需加入启动检测与导出说明。
- 当前挑战仅覆盖输出型任务，满足第一章 Demo；函数/文件类挑战留给后续章节。

## G5 · AI 师尊分级引导（2026-08-08）

### 完成内容

- 新增离线 `TutorManager`，无需 API Key 即可提供第一章全部挑战的指导。
- 六类第一章挑战各配置 L1 方向、L2 范围、L3 明确线索、L4 答案四级内容。
- 悟性达到 20 时提示加快一级；心境低于 30 时直接提供至少 L3 线索，降低挫败。
- 诊断覆盖语法错误及行号、运行异常类型、超时、内存、输出不符和桥接异常。
- 普通代码试炼新增“求师尊指点”“诊断代码”；Boss 战新增“师尊传音”。
- 师尊只提供解释与线索，不触发奖励，不绕过 Python 提交验证。

### 技术决策

- 第一章默认使用确定性的本地提示数据，保证离线、可测试和教学准确。
- 提示等级按挑战在当前会话内记录，开始新角色时重置；不把求助次数当作惩罚性永久状态。
- 外部模型仅作为未来可插拔增强，本 Demo 不让网络可用性影响主流程。

### 问题与修复

- 初版“提示文本不同”测试仅复制数组后比较长度，不能发现重复内容；改为字典键去重后断言 4 条独立提示。

- G1 至 G4 回归：60 / 60 通过。
